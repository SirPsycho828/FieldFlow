## Overview

The Files tab on the client detail page lets architects drag-and-drop photos, PDFs, and design files onto a client card. Files are automatically sorted into folders based on MIME type (Photos, Documents, Designs), stored in Firebase Storage, and tracked via Firestore metadata documents. Image uploads get automatic thumbnail previews via the Firebase Resize Images extension.

## Dependencies

- `02_Database_Schema.md` -- `files/{fileId}` subcollection shape, folder assignment rules, Storage path convention
- `03_Security_Rules.md` -- Storage upload rules (25 MB max, MIME type validation)
- `04_Cloud_Functions.md` -- Resize Images extension configuration and thumbnail path convention
- `05_UI_Design_System.md` -- Card patterns, empty states, loading states

## Data Loading

Attach a Firestore real-time listener on `users/{uid}/clients/{clientId}/files` ordered by `uploadedAt` descending when the Files tab becomes active. Detach on tab switch or page unmount.

Group results by `folder` field on the frontend for display.

### Folder Headers

Each folder header shows:
- Collapse/expand chevron (Lucide `ChevronDown`/`ChevronRight`)
- Folder name (Photos, Documents, Designs)
- File count badge

All folders start expanded. Collapse state is local UI state only, not persisted.

### File Thumbnails

Files display as a responsive grid of thumbnail cards: `grid-cols-2` on mobile, `grid-cols-3` on tablet, `grid-cols-4` on desktop. Gap of `gap-3`.

**Image files** (in Photos folder):
- Show the thumbnail image generated by the Resize Images extension
- Thumbnail path: `{storagePath}/thumbnails/{filename}_200x200.{ext}` (see `04_Cloud_Functions.md`)
- If thumbnail is not yet generated (extension hasn't processed it), show a skeleton placeholder and retry loading after 3 seconds
- Fallback: if thumbnail fails to load after 2 retries, show the Lucide `Image` icon

**PDF files** (in Documents folder):
- Show Lucide `FileText` icon in a muted background square
- No PDF preview at MVP

**Other files** (in Designs folder):
- Show Lucide `File` icon in a muted background square

### File Card Layout

Each file thumbnail card contains:

### Empty Folder

When a folder has zero files, show "No files yet" in `text-sm text-muted-foreground italic` inside the collapsed folder content area.

### Full Tab Empty State

If zero files exist across all folders, replace the folder view entirely with the standard empty state: Lucide `Upload` icon, "No files yet" heading, "Drag and drop files or click to upload" description, "Upload Files" button.

## Upload

### Drag-and-Drop Zone

The entire Files tab content area is a drop zone implemented with `react-dropzone`. Visual indicators on drag-over:

- Border changes to `border-2 border-dashed border-primary`
- Background tint: `bg-primary/5`
- Centered text: "Drop files to upload" in `text-primary font-medium`

### Upload Button

An "Upload Files" button (outline variant, Lucide `Upload` icon) appears at the top of the tab. Clicking opens the system file picker via `react-dropzone`'s click handler. Accepts multiple file selection.

### Upload Constraints

| Constraint | Value | Enforcement |
|---|---|---|
| Max file size | 25 MB per file | Client-side check via `react-dropzone` `maxSize`. Also enforced by Storage rules |
| Max files per upload | 10 files at once | Client-side check via `react-dropzone` `maxFiles` |
| Allowed types | Images (JPEG, PNG, WebP), PDFs, common design formats | Client-side `accept` config. Storage rules provide secondary enforcement |

**Rejected files**: Show an error toast listing filenames that were rejected and why (too large, unsupported type).

### Upload Flow

For each accepted file:

1. **Generate IDs**: Create a Firestore document ID for the file metadata
2. **Determine folder**: Map MIME type to folder using rules from `02_Database_Schema.md`
3. **Build Storage path**: `users/{uid}/clients/{clientId}/files/{fileId}/{originalFilename}`
4. **Upload to Storage**: Use `uploadBytesResumable` for progress tracking
5. **Write Firestore metadata**: On upload complete, write the file metadata document
6. **Update client**: In same batch, update `client.lastActivityAt` and write activity log entry (type `file_uploaded`, description includes filename)

### Upload Progress

Show upload progress inline. During an active upload, a progress section appears at the top of the file list:

```
┌───────────────────────────────────────┐
│ Uploading 3 files...                  │
│                                       │
│ site-photo-1.jpg    ████████░░  80%   │
│ site-photo-2.jpg    ██████░░░░  60%   │
│ proposal-v2.pdf     ██░░░░░░░░  20%   │
└───────────────────────────────────────┘
```

Each file shows: filename (truncated), progress bar, percentage. Use Tailwind's `bg-primary` for the filled portion, `bg-muted` for the track.

**On completion**: The progress row disappears for each file as it finishes. The file appears in the correct folder via the real-time listener. Show a success toast when all files in the batch complete: "Uploaded {n} file(s)".

**On failure**: Show an error toast with the filename that failed. Leave successfully uploaded files in place. The architect can retry the failed file.

## File Actions

### Download

Click on a file card or the download icon in the hover overlay. Call `getDownloadURL()` on the Storage reference and open in a new browser tab. For images this shows the full-resolution version.

### Delete

Delete icon (Lucide `Trash2`) in the hover overlay. Show a confirmation dialog: "Delete {filename}? This cannot be undone."

**On confirm**:
1. Delete the file from Firebase Storage (original + thumbnail if it exists)
2. Delete the Firestore metadata document
3. No activity log entry for file deletion (reduces noise)
4. No `lastActivityAt` update for deletion
5. Show success toast: "File deleted"

**Deletion is permanent**. No soft delete or trash for files.

## Thumbnail Timing

The Resize Images extension processes uploads asynchronously. There is a delay between upload completion and thumbnail availability.

**Handling the gap**:
1. After writing the file metadata document, set `thumbnailPath` to the predicted path (see `04_Cloud_Functions.md`)
2. When rendering, attempt to load the thumbnail image
3. If the image fails to load (404 -- extension hasn't processed yet), show a skeleton with a subtle pulse animation
4. Retry loading the thumbnail every 3 seconds, up to 5 attempts
5. After 5 failed attempts, fall back to the `Image` icon permanently for that render session

This avoids polling Firestore. The image element's `onError` handler drives the retry logic.

## Mobile Behavior

- File grid becomes `grid-cols-2`
- Drag-and-drop still works on mobile browsers that support it, but is not the primary interaction
- The "Upload Files" button is the main upload mechanism on mobile
- File cards are tap targets -- tap to download/view, long-press for action menu (delete)

## Gaps & Assumptions

| Gap | Default Applied |
|---|---|
| No file renaming | Files keep their original upload name. Renaming adds form complexity for minimal benefit at MVP |
| No file versioning | Uploading a file with the same name creates a separate entry. See `02_Database_Schema.md` |
| No file previews beyond thumbnails | No in-app PDF viewer, no lightbox for images. Files open in a new browser tab. Add a lightbox post-MVP for image galleries |
| No folder reassignment | Files are auto-sorted at upload. An architect cannot move a file from Documents to Designs. Rarely needed when auto-sort is based on MIME type |
| No bulk delete | Files are deleted one at a time. Acceptable at MVP file volumes |
| No storage quota display | Architects do not see how much storage they are using. At MVP scale with < 50 users, storage stays well within limits |
| Design file MIME types are broad | The "Designs" folder catches everything that is not an image or PDF. This includes DWG, DXF, SKP, and other CAD formats, but also any unexpected file type. Acceptable categorization for MVP |
| No virus scanning on uploads | Firebase Storage does not scan uploads. The risk is low with a small trusted user base. Consider adding Cloud Functions-based scanning post-MVP if the app opens to wider audiences |
